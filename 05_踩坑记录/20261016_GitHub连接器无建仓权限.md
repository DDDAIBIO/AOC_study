# 坑：GitHub 连接器无法创建仓库（403 Resource not accessible by integration）

- **现象**：让 AI 助手直接建 `oligo-kb` 仓库，返回 `403 Resource not accessible by integration`。
- **当时的错误理解**：以为连上 GitHub 账号就等价于拿到完整读写权限，可以直接建仓改文件。
- **正确结论**：WorkBuddy 的 GitHub 走的是 **GitHub App 集成身份**，权限受限于安装时授权的仓库范围，**默认不含「创建仓库」**。能做的：读写已授权仓库的文件、issue、PR、commit 查询。不能做的：新建仓库、改账号级设置。
- **代价**：约 10 分钟试错。
- **怎么避免**：建仓这类账号级操作走两条路——
  1. **网页手动建仓**（github.com/new，私有，不勾选任何初始化选项），再用 SSH/HTTPS 推；
  2. 给一个 **fine-grained PAT**（勾选 repo 全部权限），让工具带 token 操作。
- **本次解法**：本地 `git init` + 首次提交 → 生成专用 SSH key（`~/.ssh/id_ed25519_oligokb`，已写入 `~/.ssh/config` 的 `Host github.com` 段）→ 网页加 SSH key + 建空仓库 → `git push -u origin main`。
- **备注**：若已有个人 PAT，HTTPS 方式更快；SSH 方式一劳永逸，后续每天 commit 推送无感。

## 附带教训：Windows 上批量改中文文件名会翻车

- **现象**：为修复一个乱码文件名写 Python 批量重命名脚本，条件判断 `'术' in f` 误命中目录 `02_技术方案`，把目录改名成了文件目标名。
- **怎么避免**：批量重命名前先 `print(repr(f))` 看清真实字符；先 `os.path.isdir()` 区分目录与文件；先挪到临时名再改正式名，别一步到位。
